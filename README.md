# VitestDedup website

The official website for [VitestDedup](https://github.com/figueiredoluiz/vitest-dedup), a static
analyzer that finds duplicate and near-duplicate Vitest tests.

Built with [Astro](https://astro.build) + [Starlight](https://starlight.astro.build) for
documentation, Tailwind CSS v4 for the design system, and Pagefind search through Starlight's
built-in integration. Fully static: no backend, no runtime server-side processing.

## Getting started

Requires Node 20+ and [pnpm](https://pnpm.io).

```sh
pnpm install
pnpm dev
```

The dev server serves at <http://localhost:4321>.

Production build and local preview:

```sh
pnpm build
pnpm preview
```

Documentation search (Pagefind) indexes at build time, so test it in `pnpm preview`, not `pnpm dev`.

## Configuration

- **`SITE_URL`** (env) — canonical origin used for metadata and the sitemap. Defaults to
  `http://localhost:4321`, so built pages never carry a fictitious production domain. Set it when
  deploying.
- **`src/lib/site.ts`** — site-wide config: repository URL, npm URL, current version. Emptying
  `repoUrl` hides every GitHub call to action across the site.

## Data sources and what is mocked

Content was written against the actual VitestDedup source repository (`docs/`, `README.md`, release
tags), so CLI commands, flags, rules, reporters, and exit codes are real.

- `src/data/releases.json` — real tag names and dates (v0.1.0–v0.5.0) with summary bodies written
  for this site; each entry links to the original GitHub release. Shaped after the GitHub Releases
  API so it can be replaced with build-time fetches later.
- `src/data/sample-report.json` — generated by `node demo/generate-sample-report.mjs <binary>`
  from a real run of the CLI on a generated ~1,000-test project (`demo/generate-sample-project.mjs`), reshaped for the report components. The
  terminal sample in `Hero.astro` is the same run's output; update both when the version changes.

## Theming

Landing pages and Starlight share one theme: both drive the `data-theme` attribute on `<html>` and
the `starlight-theme` localStorage key, so a single toggle keeps dark/light in sync across the whole
site. Brand tokens live in `src/styles/tailwind.css`; Starlight's palette is aligned in
`src/styles/starlight.css`.

## Deployment

Production hosting is Cloudflare Pages, published by the GitHub Actions workflow in
`.github/workflows/deploy.yml` (direct upload via wrangler, not the Git integration).

- Canonical domain: **vitestdedup.dev** (apex; `www` 301-redirects to it) — set at build time
  through `SITE_URL`, which feeds canonical URLs, Open Graph tags, and the sitemap.
- Pages project: `vitest-dedup-site`.
- Required repository secrets: `CLOUDFLARE_API_TOKEN` (Account → Cloudflare Pages → Edit) and
  `CLOUDFLARE_ACCOUNT_ID`.
- Triggers: pushes to `main` (production), pull requests (previews), manual `workflow_dispatch`,
  and `repository_dispatch` (`release-published`), which the VitestDedup source repository's
  release workflow can fire to rebuild the site when a new version ships.

### Analytics

Google Analytics 4 loads only when `PUBLIC_GA_ID` is set (a GitHub Actions **variable**, not a
secret — measurement ids are public). Unset locally, so `pnpm dev` never tracks. Docs-search terms
are reported as GA `search` events; enable Enhanced Measurement in the GA admin for scrolls,
outbound clicks, and downloads.

### Release notes

The changelog fetches releases from the GitHub Releases API at build time (authenticated with the
workflow's `github.token` when available) and falls back to the local fixture
`src/data/releases.json` when the API is unreachable.

### Documentation sync

The Analyzer Reference section under `/docs/reference/` is generated from the VitestDedup source
repository's published `docs/` (the same file set the npm package ships — internal `*.local.md`
notes and working documents are excluded):

- `pnpm sync:docs` regenerates `src/content/docs/docs/reference/` from a local clone
  (default `../vitest-dedup`, override with `VITEST_DEDUP_REPO`). The output is committed so
  builds stay deterministic and offline-friendly.
- CI checks out the source repo and re-runs the sync before every build, so deploys always carry
  the latest upstream docs even without a manual sync.
- Each generated file carries a provenance comment naming the source commit. Edits belong
  upstream; the curated website docs remain hand-written.

### Social preview image

`public/images/og.png` (1200×630) is referenced by Open Graph and Twitter card tags on every
page. Regenerate after brand changes with `pnpm og:image`.
